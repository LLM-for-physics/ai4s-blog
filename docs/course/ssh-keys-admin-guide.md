# 助教公钥管理操作说明

[打开助教管理页面](/course/ssh-keys-admin)。使用预先登记的管理员邮箱接收验证码，登录后可以查看名单和公钥。

## 1. 准备选课名单

在管理页面展开“导入或更新选课名单”，下载 Excel 或 CSV 模板。名单需要“学号、姓名、服务器号”三列，服务器号必填 `132`、`190` 或 `197`；学号按文本填写，保留前导零，不使用科学计数法。

邮箱自动生成为 `学号@stu.pku.edu.cn`，Linux 用户名为 `stu` 加完整学号。例如 `0012345678` 对应用户名 `stu0012345678`、邮箱 `0012345678@stu.pku.edu.cn`。每位学生的目标服务器由名单第三列指定，学生不能修改。

管理员可按课程安排在三台服务器之间分配学生，页面只统计当前分配人数，不会重新均分或改动已有分配。132、197 的安装通道需要另外部署和核验，名单能够填写这些编号不代表它们已经可用。

选择文件后点击“检查并预览名单”。核对新增、更新、目标服务器、用户名及错误行，再点击“确认保存名单”。存在错误时本次名单不会部分保存；后续更新名单也不会因为某一行消失就移除学生或撤销公钥。文件中出现已移除学生会提示错误，重复导入不能自动恢复该记录；应先在“已移除学生”中明确恢复。

**导入名单只建立课程网站记录，不会创建 Linux 账号。** 名单录入后，已开放的提交页面才允许这些学生验证邮箱。

## 2. 核对提交情况

管理表格可以按学号、姓名或用户名搜索，按 132、190、197 服务器筛选，也可以筛选未提交、待处理、导入失败和账号待准备等状态。顶部人数卡只统计在册学生，不改变实际分配。默认显示在册名单，可在“名单范围”切换到“已移除学生”。

“✓ 已提交”表示已收到通过后端校验的公钥。“指纹与完整公钥”可以展开查看和复制标准公钥，使用“导出在册 Excel”可以保存名单、状态与完整公钥内容。

“最近提交”与“已安装”可能是不同版本。学生上传新公钥后，服务器上原课程公钥保持有效，直到新版本安装成功。

## 3. 检查服务器账号

勾选学生后点击“检查所选账号”。页面区分：

| 结果 | 下一步 |
| --- | --- |
| 已就绪 | 可以进入公钥导入预览 |
| 账号不存在，待创建 | 由管理员在指定服务器创建 `stu` 加完整学号的 Linux 账号，再准备安装允许清单 |
| 待授权 | 管理员核对该账号的实际 UID 并加入安装允许清单 |
| 检查失败 | 查看错误信息，恢复服务器安装服务后重新检查 |

学生可以在账号准备好之前提交公钥。目标 Linux 账号必须已存在并经过 root 管理员授权，网站不会创建账号或放宽安装授权。补建账号并授权后，等待中的自动候选会继续检查；助教也可人工重新检查、导入，无需学生重传。

## 4. 启动或停止自动导入

自动导入默认关闭。管理页面的“自动导入公钥”卡片显示当前状态及最近设置人、设置时间。

1. 核对目标服务器账号和 root 授权准备情况，点击“启动自动导入公钥”。
2. 阅读确认说明。自动模式同时适用于首次上传与后续换钥，新公钥导入成功后会替换该学生原课程公钥。
3. 点击“确认启动自动导入”。只有开关开启后新提交的公钥会进入自动处理；开启前已保存的公钥不会补导入，请使用人工预览确认处理。重复上传同一把公钥也不会给旧提交补建自动任务。
4. 账号缺失或尚未授权时，自动候选保留并由后台持续检查，账号准备好后继续处理，无需学生重传。在学生行查看等待或受阻原因，在“导入与撤销记录”查看标记为“自动导入”的批次结果。
5. 停止时点击“停止自动导入”，阅读说明后点击“确认停止自动导入”。尚未批准的候选会取消；已入队的任务仍会继续完成。停止后新提交等待人工导入。

启动和停止都需要最近十分钟内的管理员验证。若其他管理员同时更改开关，页面会重新加载当前状态，需核对后再次确认。不要因请求超时重复判断开关状态，先点击“刷新自动导入设置”。

自动导入开关不改变学生提交入口的开放范围。试用期间仍仅向指定测试学生开放；开启自动导入不会开放全班。

## 5. 预览并确认人工导入

1. 勾选需要处理的学生。表头复选框只选择当前筛选结果；页面会提示是否还有筛选之外的已选学生。
2. 点击“预览导入”。核对姓名、学号、目标服务器、`stu` 用户名与公钥指纹。
3. 不符合条件的条目会说明原因。确认按钮只处理标为“可执行”的条目。
4. 点击“确认导入”，在“导入与撤销记录”中查看每个账号的结果。

预览有有效期。预览后学生公钥或名单发生变化，系统会要求重新预览，不会静默导入另一把公钥。

执行导入、公钥撤销或恢复、名单移除或恢复前，需要最近十分钟内的助教身份验证。页面提示重新验证时，之前的选择和预览会保留；验证后检查预览并再次点击确认。

## 6. 查看失败和重试

页面可见时运行中的批次会自动更新，自动导入开启时也会发现新的自动批次。每条批次区分“自动导入”和“人工操作”。部分失败不会撤回已经成功的项目；修复账号准备或服务问题后，点击“重试失败项”。已经被更新版本替代的旧任务不能覆盖新版本。

如果请求超时或连接中断，先刷新记录核对实际结果，再决定重试。“已导入”表示服务器完成写入并核对；请让学生自行用对应私钥进行实际 SSH 登录验证。

## 7. 撤销或恢复历史公钥

- **撤销**：在学生行点击“撤销”，检查预览后确认。只撤销本系统管理的课程公钥，同时暂停该学生的自动导入，学生再次上传不会解除暂停。
- **恢复**：进入“历史公钥”，找到需要恢复的版本，点击“预览恢复此公钥”，核对后确认。恢复会替换当前课程公钥。人工导入或恢复成功后，才解除该学生的自动导入暂停。

服务器上此前另外配置的个人公钥不受课程公钥操作影响。上述操作均会保留审计和批次记录。

## 8. 移除和恢复名单

**移除名单保留 Linux 账号、公钥历史和操作记录，不代替公钥撤销。** 只有没有已安装课程公钥、没有未完成或结果不确定的任务时，后台才允许移除。

1. 在在册列表点击学生行的“移除名单”，或勾选多人后点击“预览移除名单”。
2. 预览会逐项解释是否可移除。有已安装公钥时，先取消预览并手动撤销，等待任务成功；存在待处理或不确定任务时先核对其结果。
3. 核对后点击“确认移除名单”。该学生从默认列表隐藏，原网站登录与验证码失效，不能继续提交。
4. 在“名单范围”切换到“已移除学生”，可以查看保留的记录和公钥历史。
5. 需要重新加入时点击“恢复名单”，预览并确认。恢复只重新允许学生验证邮箱和提交，不会自动安装历史公钥；学生需要重新登录。

重复上传包含已移除学生的名单不会恢复记录。移除或恢复不会自动均分服务器，也不会删除或重建 Linux 账号。

## 日常检查

课程开放前，先用指定测试邮箱和测试账号完成验证码、首次自动导入、换钥及真实 SSH 登录验证。试用完成后是否开放全班，以课程负责人明确通知为准；自动导入开关不会扩大提交权限。准备期间也应检查邮箱服务发送额度与实际送达情况。

网站服务暂不可用或邮件未配置时，学生页面会显示说明。学生提交入口尚未开放时，助教仍可登录完成名单和账号准备。发件邮箱凭据、管理员白名单和开启入口的设置由服务器管理员管理，不在网页中公开。
