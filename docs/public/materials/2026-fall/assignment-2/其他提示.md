# 其他提示

## 没有灵感时

想一想：哪些要求需要反复向 AI 解释？哪些结果总要自己返工？哪些工作每次步骤相似、输入不同？

从一件小事开始，例如按个人偏好筛选论文、整理实验文件、汇总仿真结果。没有科研经历，也可以选择学习和日常资料整理中的需求。甚至是你自己平时使用AI时，有一些AI总是让你费口舌的地方，也可以尝试用skill来改进。

## 还是没有灵感，可以去哪里看看大家平时用什么

- [Skills.sh](https://www.skills.sh/)：Vercel 维护的技能目录，可按主题、关键词和热度查找，适合先找方向。
- [SkillsMP](https://skillsmp.com/)：聚合 GitHub 上的 Skills，可按任务和领域搜索，再到原仓库查看内容。
- [Anthropic 官方示例仓库](https://github.com/anthropics/skills)：阅读完整的 Skill 结构与实现，其中 [skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) 可参考创建流程。
- 也可以阅读自己所用 AI 平台已有的 Skills。

参考后说明来源，以及为自己的需求做了哪些修改。收录和排名不代表质量或安全认证；[Skills.sh](https://www.skills.sh/docs) 与 [SkillsMP](https://skillsmp.com/) 均有相应说明。



## 参考第三方 Skill 时的提醒

- **先看再用。** 核对作者与原仓库，阅读 `SKILL.md`、引用文件和脚本后再加载。第三方 Skill 可能含恶意指令；仅有 Markdown 也可能诱导 AI 执行危险操作。
- **看不懂的命令不要直接执行。** 尤其警惕下载并运行陌生脚本、无关的删除或权限修改、索取密钥、向陌生网址上传私密文件。
- **限制试用范围。** 尽量在权限受限的沙箱中使用测试副本，不放真实密钥和隐私资料。单独建立测试文件夹不等于隔离环境。
- **检查不等于安全保证。** 下载量、平台扫描和 AI 审查都只能作参考。不确定时先参考设计思路，暂不加载或执行，向助教求助。

更多说明见 [Anthropic 的 Skill 安全建议](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills#security-considerations-when-using-skills)。

## 创建 skills 时注意

- 创建前先确认平台怎样保存或导出对话，避免完成后找不到记录。
- 文件管理类的skill先在测试副本上试用（防止开发过程中AI给你真实文件不小心全清了）。
- Skill 需要的搜索、文件读写或计算工具，应由所用平台提供。
- 脱敏时可用“[sensitive/private content]”替换敏感内容，并检查对话、工具输出和截图。
- 脚本按需添加；无需为了显得复杂而增加代码、MCP 或多 Agent。
