# 1. 写出一次 MCTS 搜索

本篇对应 `starter/mcts.py`：补全选择、扩展、回传和搜索循环。游戏规则、网络调用已提供；完成后删去对应的 `raise NotImplementedError(...)`。

## 认识节点与接口

一个 `Node` 表示一个局面，`node.player` 是接下来落子的一方。

| 字段 | 含义 |
| --- | --- |
| `board`、`player` | 棋盘、行棋方 |
| `children` | 字典：列编号 → 落子后的节点 |
| `prior` | 父节点走向该节点的先验概率 |
| `visits` | 访问次数 |
| `value_sum` | 从该节点行棋方视角累计的价值 |

棋盘中 `0` 为空，`1` 为红方，`-1` 为黄方；列编号为 `0～6`。用 `node.children[col]` 取得对应子节点，用 `node.children.values()` 遍历所有子节点。

以下接口可以直接调用：

| 调用 | 返回结果 |
| --- | --- |
| `Node(board, player, prior)` | 一个新节点 |
| `legal_moves(board)` | 尚未填满的列编号列表 |
| `play_move(board, col, player)` | 落子后的新棋盘，不修改原棋盘 |
| `next_player(player)` | 另一方的编号 |
| `game_result(board)` | `done, winner`：是否结束、获胜方；平局时 `winner=0` |
| `evaluate_position(model, board, player)` | `priors, value`：七列的先验概率、当前行棋方的价值 |

## 第一步：选择分支

在 `select_child` 中比较各子节点的 PUCT 分数，返回最高分对应的节点：

$$
Q+cP\frac{\sqrt{N+1}}{n+1}.
$$

`Q` 用 `child.mean_value(node.player)` 取得；`P` 是 `child.prior`，`N` 是父节点访问次数，`n` 是子节点访问次数，`c` 对应参数 `c_puct`。

第一项偏向已经看好的选择，第二项鼓励探索。用 `for` 循环比较即可，最高分初值可设为 `-float("inf")`。平方根内加一是本作业的简化约定。

## 第二步：扩展节点

在 `expand` 中遍历合法列。每列调用 `play_move` 得到新棋盘，用 `next_player` 取得下一方，以 `priors[col]` 为先验概率创建 `Node`，存入 `children[col]`。

扩展列出的是各个可能的下一步，不是在同一棋盘上连续落子。

## 第三步：回传价值

`path` 保存本次搜索经过的节点，包含根节点，最后一个是叶节点。传入 `backpropagate` 的 `value` 属于叶节点行棋方的视角。

遍历路径，为每个节点增加一次访问，并累计转换到该节点视角的价值。转换接口为：

```python
convert_value(value, from_player, to_player)
```

例如黄方视角的 `+0.8`，转到红方就是 `-0.8`；调用转换后不要额外取负号。这里的回传只更新节点统计量，不是 `loss.backward()`，也不修改网络参数。

## 第四步：组成搜索循环

根节点已初始化并扩展。每次模拟从根节点开始，建立新的 `path`：

1. 只要节点有子节点，就调用选择函数向下走，并记录路径。
2. 用 `game_result` 判断停下来的节点是否为终局。
3. 若已结束，用 `result_value(winner, node.player)` 得到真实价值；否则调用网络获取先验概率和价值，再扩展。
4. 回传本次评估结果。

终局价值仍按该节点行棋方计算：对方刚刚获胜时，应为 `-1`。非终局由网络评估，不需要随机下完整盘棋。

完成 `simulations` 次模拟后，返回各列访问次数。在本骨架中，这些次数之和应等于 `simulations`，满列的次数为 `0`。
