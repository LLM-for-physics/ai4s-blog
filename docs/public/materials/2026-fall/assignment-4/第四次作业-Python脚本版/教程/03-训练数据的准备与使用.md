# 3. 训练数据的准备与使用

加法题能直接计算答案，PINN 用方程约束输出。本题则在自我对弈中产生数据：`pi` 来自当前搜索，`z` 来自实际对局结果。搜索分布不保证最优，单盘胜负也不能直接当作该局面的理论价值。

## 1. 一条样本是什么？

每次落子前的局面形成一条 `(state, pi, z)` 样本：

| 内容 | 含义 | 单个样本的形式 |
| --- | --- | --- |
| `state` | 当前行棋方视角的棋盘编码 | `[3, 6, 7]` 的浮点 Tensor |
| `pi` | 搜索访问次数归一化后的分布 | 长度为 7 的 NumPy 数组 |
| `z` | 该行棋方最终胜、负、平的结果 | `+1`、`-1` 或 `0` |

三个通道依次表示我方棋子、对方棋子和空格，每格为 `0` 或 `1`。`encode` 已提供转换，可将下面的例子保存为 `starter/try_data.py`。在 `starter` 目录、`pubpy` 环境中运行 `python try_data.py`：

```python
from support.game import new_board, play_move, encode

board = play_move(new_board(), 3, 1)  # 红方先在编号 3 的列落子
state = encode(board, -1)            # 接下来轮到黄方
print(state.shape)                  # torch.Size([3, 6, 7])
print(state.dtype)                  # torch.float32
print(state[1, 5, 3].item())         # 1.0：黄方视角中，这枚棋子属于对手
```

一盘棋产生多条样本。必须保存**落子前**的局面，以及对这个局面搜索得到的 `pi`，不能将 `pi` 配到落子后的棋盘。

## 2. 从一盘棋到训练批次

```text
history：落子前暂存 (state, pi, player)
    ↓ 对局结束，按记录时的行棋方生成 z
examples：一盘棋的多条 (state, pi, z)
    ↓ 合并多盘棋
replay：近期训练样本
    ↓ 随机抽取并组批
states、target_pi、target_z：本次参数更新使用的数据
```

`history` 暂存行棋方，是因为结束后才能填写胜负标签。红方获胜时，红方局面标 `+1`，黄方局面标 `-1`，不能给整盘所有局面都标成 `+1`。

训练循环已用 `replay.extend(...)` 逐条加入一盘棋的样本；不要改成 `append(...)`，那会把整盘列表作为一条记录加入。

## 3. `sample_batch` 帮你做了什么？

`sample_batch(replay, BATCH_SIZE, DEVICE)` 随机抽取完整样本，再组成三个张量：

| 变量 | 形状 | 内容 |
| --- | --- | --- |
| `states` | `[B, 3, 6, 7]` | `B` 个棋盘 |
| `target_pi` | `[B, 7]` | 各棋盘的七列目标概率 |
| `target_z` | `[B]` | 各棋盘的胜负标签 |

内部用 `torch.stack` 堆叠棋盘，将 `pi`、`z` 转成 Tensor，并统一为 `float32`、放到指定设备。与 PINN 对坐标求导不同，本题只需要网络参数的梯度，不必给棋盘和标签设置 `requires_grad=True`。

抽样是**有放回的**，同一条记录可能重复出现。始终按完整样本抽取，不能分别打乱输入和标签。

可在 `train.py` 已有的 `sample_batch(...)` 调用后临时加入以下调试片段，不能单独运行：

```python
print(states.shape, target_pi.shape, target_z.shape)
print(states.dtype, states.device)
print(target_pi[0].sum().item())  # 第一条策略目标的概率之和应接近 1
print(target_z[:5])              # 查看前几个标签
```

## 4. 为什么保留近期数据？

每轮都会新增对局。随机抽批让一次更新能利用多盘棋的经验；`replay[-MEMORY_SIZE:]` 只保留最近的一定数量样本，限制内存占用，也避免缓存一直积累早期数据。

样本保存在运行时内存中，不需要另存数据集。`model.pt` 只保存网络参数，不包含缓存；当前骨架不自动续训，修改 `RUN_DIR` 后重新运行，会重新初始化网络和收集数据。

**选读：其他数据工具。** 对固定数据集，`TensorDataset` 可将输入和标签配对，`DataLoader` 负责分批和打乱顺序。本作业已有适合动态对局数据的 `sample_batch`，无需替换。[官方数据教程](https://docs.pytorch.org/tutorials/beginner/basics/data_tutorial.html)

## 5. 检查

- 局面与 `pi` 一一对应，均来自落子前。
- `pi` 非负、和接近 `1`，满列的目标概率为 `0`。
- `z` 按记录时的行棋方确定；平局为 `0`。
- 组批后的形状与上表一致，尤其是 `target_z` 为 `[B]`。
