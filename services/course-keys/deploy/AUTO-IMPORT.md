# 自动导入公钥：运维与升级

管理员页面提供“启动自动导入公钥”和“停止自动导入”功能，默认关闭。开启与停止需要最近十分钟内完成管理员验证，并检查 CSRF、请求来源和设置版本。

## 行为

- 开启后的新有效公钥提交可自动导入，首次及后续换钥均适用。开关不会导入以前已经提交的公钥；同一公钥重复提交不会重新批准安装。
- 使用名单中分配的 132、190、197 服务器及 `stu` 加学号的用户名。学生不能覆盖这些字段。
- 仅对在册、当前开放范围内的学生处理。账号存在、UID 与 root 允许清单相符且安装检查通过后，才进入已有的持久安装队列。
- 账号缺失或尚未授权时保存公钥，后台延迟重查，无需再次上传。不会创建账号或修改 root 允许清单。
- 换钥经过相同队列与结果核验。旧公钥保留到新版本成功写入；每次自动批准有独立审计，批次来源标记为 automatic。
- 关闭会取消尚未批准的自动候选，已经批准入队的任务继续完成。再次开启不会重新批准取消的候选。
- 手动撤销会暂停该学生自动导入，之后的新提交也不能绕过。管理员手动导入或恢复成功后，才解除该学生的暂停；暂停期间的候选不会自动复活。
- 已批准任务的通信重试复用 requestId，明确执行失败或结果不确定时交给管理员处理，不无限创建新版本。
- 学生页面可见时自动刷新结果。“已导入”表示服务器写入并核验成功，实际 SSH 登录仍使用学生持有的私钥验证。

## 数据库与部署

Web 数据库升级为 schema 3，新增开关、候选、单个学生暂停状态和批次来源；导入服务数据库继续为 schema 2。升级保留名单、邮箱、服务器分配、公钥版本、安装结果、历史记录及会话。默认关闭，历史撤销记录保守迁移为暂停自动导入。

发布前停止 Web 并运行一致性备份；在数据库副本中以 Web 服务用户预检升级，再切换 root 所有的服务发布目录并启动 Web。后台安装服务和三台服务器的 SSH 配置无需修改。验证真实 Web 版本、数据库完整性、备份可恢复性以及试用配置后发布页面。

首次部署本功能时仅向测试学号 `2501110104` 开放，这是当时的试用约束。之后已按用户授权向全体在册学生开放，见[正式开放记录](ENROLLMENT-OPEN-20260918.md)。应用升级本身不应改变开放范围、名单或安装允许清单；这些设置按管理员单独确认的运维操作处理。

## 回滚

如需暂停新批准，管理员关闭自动导入。数据库与已经安装的公钥继续保留。

旧 schema 2 Web 程序不能直接读取 schema 3。应用故障应部署兼容 schema 3 的修复版本；不要只把服务软链接指回 schema 2 程序。回退数据库需要停服、人工核对备份之后的提交及实际安装版本，不能覆盖新记录或回退服务器公钥 generation。静态网页可单独回滚，但管理新功能应使用匹配页面。

## 验证范围

新增测试覆盖开关权限、首次与后续换钥、关闭与异步检查竞态、缺失账号后恢复、重复上传、撤销暂停、名单/目标变化、持久状态、旧批次结果不倒写新版本、120 名模拟学生和浏览器交互。所有自动测试使用隔离数据与模拟邮件；不会发送全班邮件、替换真实学生公钥或自动创建 Linux 账号。

跨服务器调度的已知等待边界见[已知问题](../KNOWN-ISSUES.md)。
